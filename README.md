# موقع شركة المواهب

موقع مؤسسي متعدد الصفحات واللغات لشركة «شركة المواهب للاخراج والتخليص الكمركي محدودة المسؤولية»، مبني بـ PHP وHTML5 وCSS3 وVanilla JavaScript، مع MySQL ولوحة إدارة عربية.

## نسخة GitHub

يتضمن المستودع ملفات الموقع والوسائط العامة والاختبارات وملفات إنشاء قاعدة البيانات والمحتوى الأولي. لا يتضمن `.env` أو كلمات المرور أو حساب الإدارة الحالي أو طلبات التواصل أو بيانات MySQL المحلية أو نسخها الاحتياطية أو السجلات أو الملفات المرفوعة من لوحة الإدارة. تبقى هذه البيانات على الجهاز ولا تُحذف عند رفع الكود.

بعد تنزيل نسخة جديدة، اتبع تعليمات التشغيل أدناه لإعداد MySQL وإنشاء حساب إداري خاص بك. رفع الكود إلى GitHub لا يشغّل PHP أو MySQL؛ تشغيل الموقع العام يحتاج استضافة تدعمهما، وليس GitHub Pages.

## المتطلبات

- PHP 8.2 أو أحدث، مع إضافات: `pdo_mysql`, `mbstring`, `fileinfo`, `json`, `openssl`, `gd`.
- MySQL 8.0 أو أحدث، أو MariaDB 10.6 أو أحدث.
- Apache مع `mod_rewrite` أو Nginx.
- اجعل `public/` هو مجلد الويب العام Document Root. لا توجّه الخادم إلى جذر المشروع.

## التشغيل المحلي

### زر تشغيل بنقرة مزدوجة على macOS

انقر مرتين على [تشغيل الموقع.command](تشغيل%20الموقع.command). في أول مرة ينشئ إعداداً محلياً، ويهيّئ MySQL معزولاً داخل المشروع على المنفذ `3307`، ويثبت محتوى الموقع، ثم يفتح المتصفح تلقائياً. لا يتدخل المشغّل في XAMPP أو خدمات MySQL الأخرى على الجهاز. في التشغيلات التالية يفتح الموقع مباشرة إذا كان الخادم يعمل.

لإيقاف PHP وMySQL المحليين الخاصين بالموقع استخدم [إيقاف الموقع.command](إيقاف%20الموقع.command). لا يوقف الزر أي خدمة مشتركة مع المشاريع الأخرى.

زر التشغيل لا ينشئ كلمة مرور إدارية تلقائية. لإنشاء الحساب الإداري بعد أول تشغيل، افتح Terminal داخل مجلد المشروع ونفّذ `php scripts/install.php --skip-seed`؛ سيطلب بريدك وكلمة مرور من 12 محرفاً على الأقل من دون حفظ كلمة مرور ثابتة في الكود.

إذا منع macOS فتح الملف أول مرة، انقر عليه بزر الفأرة الأيمن واختر **فتح**، ثم وافق على التشغيل.

### حساب قاعدة البيانات المحلية

أُصلح اتصال هذه النسخة المحلية بتاريخ 2026-09-12 باستخدام حساب مخصص للموقع، بكلمة مرور عشوائية محفوظة في `.env` بصلاحية ملف `600`. صلاحياته محصورة في `SELECT, INSERT, UPDATE, DELETE` على قاعدة `almawaheb`؛ ليس حساب لوحة الإدارة، ولا يملك صلاحيات إدارة مستخدمي MySQL أو إيقاف قواعد أخرى.

يدعم زر التشغيل هذا الحساب عند تشغيل قاعدة المشروع الموجودة على `127.0.0.1:3307`. ويتحقق من نجاح تسجيل الدخول باستعلام فعلي؛ لا يعيد تهيئة البيانات إذا رُفضت كلمة المرور أو فُقد مجلد البيانات. زر الإيقاف يوقف عملية MySQL المحلية الخاصة بالمشروع بأمان، دون منح حساب الموقع صلاحية `SHUTDOWN` عامة.

إذا ظهرت رسالة `Access denied`، راجع `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS` محلياً دون نشر كلمة المرور. لا تعِد تشغيل المثبّت أو تهيئة قاعدة فارغة لمعالجة خطأ الدخول. إنشاء الجداول أو ترحيلات البنية مستقبلاً يحتاج حساب تثبيت بصلاحيات مناسبة؛ حساب التشغيل الحالي لا يغيّر بنية القاعدة.

حُفظت نسخة احتياطية للبيانات وإعداد الاتصال السابق قبل الإصلاح داخل `storage/backups/`، خارج مجلد الويب ومستثناة من Git. تحتوي النسخة على بيانات خاصة؛ لا تنشرها أو ترفعها إلى `public/`.

### التشغيل اليدوي

1. أنشئ قاعدة بيانات ومستخدماً بصلاحيات عليها:

```sql
CREATE DATABASE almawaheb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'almawaheb_user'@'localhost' IDENTIFIED BY 'use-a-strong-password';
GRANT ALL PRIVILEGES ON almawaheb.* TO 'almawaheb_user'@'localhost';
```

2. انسخ `.env.example` إلى `.env` في جذر المشروع، ثم حدّث إعدادات قاعدة البيانات والرابط. أنشئ `APP_KEY` عشوائياً بهذا الأمر:

```bash
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

3. ثبّت الجداول والمحتوى الأولي وأنشئ الحساب الإداري. لا توجد كلمة مرور ثابتة في الكود؛ سيطلب المثبّت كلمة المرور تفاعلياً:

```bash
php scripts/install.php --admin-email=admin@example.com --admin-name='مدير الموقع'
```

> شغّل المثبّت أول مرة فقط. إعادة تشغيله مع البيانات الأولية قد تعيد نصوص الصفحات والخدمات إلى النسخة المرفقة بالمشروع.

4. شغّل خادم PHP المحلي:

```bash
php -S 127.0.0.1:8080 router.php
```

ثم افتح:

- الموقع العربي: `http://127.0.0.1:8080/ar/`
- الإنجليزية: `http://127.0.0.1:8080/en/`
- الكوردية السورانية: `http://127.0.0.1:8080/ku/`
- لوحة الإدارة: `http://127.0.0.1:8080/admin/login`

## الرفع إلى الاستضافة

### Apache

وجّه النطاق إلى مجلد `public/`. ملف [public/.htaccess](public/.htaccess) يمرّر المسارات غير الثابتة إلى `index.php`. تأكد من تفعيل `AllowOverride All` و`mod_rewrite`.

### Nginx

استخدم [deploy/nginx.conf.example](deploy/nginx.conf.example) كنقطة بداية، وعدّل النطاق ومسار المشروع ومقبس PHP-FPM. يحتوي المثال على منع تنفيذ PHP داخل مجلد الرفع.

### الصلاحيات

يحتاج خادم الويب إلى الكتابة فقط داخل `public/uploads/` عند استخدام رفع الوسائط. اجعل بقية ملفات المشروع للقراءة فقط بالنسبة إلى مستخدم خادم الويب قدر الإمكان. لا ترفع `.env` إلى مستودع عام، ولا تضعه داخل `public/`.

لرفع الملف التعريفي الكبير اضبط `upload_max_filesize=100M` و`post_max_size=105M` في إعدادات PHP على الاستضافة.

## إعداد SMTP

النموذج يحفظ الطلب في MySQL أولاً. إذا كانت بيانات SMTP مكتملة، يحاول بعدها إرسال إشعار. لا تظهر رسالة للزائر تدّعي إرسال البريد؛ الرسالة تؤكد حفظ الطلب فقط.

اضبط في `.env`:

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_ENCRYPTION=tls
SMTP_USER=account@example.com
SMTP_PASS=app-password-or-secret
SMTP_FROM=info@almawaheb-co.com
SMTP_FROM_NAME=شركة المواهب
SMTP_TO=info@almawaheb-co.com
```

- استخدم `tls` عادةً للمنفذ 587، أو `ssl` للمنفذ 465 بحسب مزوّد البريد.
- إذا بقي `SMTP_HOST` فارغاً، تُحفظ الطلبات دون محاولة إرسال.
- راقب سجل أخطاء PHP على الاستضافة لمعرفة أخطاء SMTP دون كشفها للزائر.

## لوحة الإدارة

توفر اللوحة وظائف فعلية مرتبطة بـ MySQL:

- تحرير محتوى الصفحات لكل لغة، وحفظ المسودة، والمعاينة للمستخدم المسجّل، ثم النشر.
- حالة اعتماد مستقلة للترجمة. النسخة الكوردية الأولية كاملة لكنها موسومة «بحاجة إلى مراجعة لغوية».
- إضافة الخدمات وتعديلها وترتيبها وإخفاؤها أو نشرها باللغات الثلاث.
- قراءة طلبات التواصل وتغيير حالتها: جديد، قيد المتابعة، مغلق.
- تعديل بيانات الاتصال والعناوين وساعات العمل والروابط الاجتماعية والخريطة.
- رفع الشعار والصورة الرئيسية والملف التعريفي بعد فحص النوع والحجم.
- تغيير البريد الإداري والاسم وكلمة المرور بعد التحقق من كلمة المرور الحالية.

## الأمان

- PDO واستعلامات معلّمة، وترميز مخرجات HTML، والتحقق على الخادم.
- رموز CSRF لكل عمليات POST.
- `password_hash` و`password_verify`، وتجديد معرّف الجلسة بعد الدخول وتغيير الحساب.
- تحديد محاولات تسجيل الدخول وطلبات التواصل في MySQL.
- فحص MIME والحجم وصلاحية الصور، وأسماء عشوائية للرفع، ومنع تنفيذ السكربتات داخل `uploads/`.
- ترويسات CSP و`X-Content-Type-Options` و`X-Frame-Options` وسياسة referrer وصلاحيات المتصفح.
- الأسرار خارج المجلد العام في `.env`، مع نموذج إعداد بلا أسرار.

## SEO والوصول

- عنوان ووصف مستقلان لكل صفحة ولغة، وروابط `canonical` و`hreflang`.
- Open Graph وبيانات Organization المنظمة بالمعلومات المؤكدة فقط.
- خريطة موقع ديناميكية على `/sitemap.xml` وملف `robots.txt` وصفحة 404 محلية.
- اتجاه RTL للعربية والكوردية وLTR للإنجليزية، وخصائص CSS منطقية.
- تنقل بلوحة المفاتيح، مؤشر تركيز واضح، تسميات للنماذج، ونمط `prefers-reduced-motion`.
- الصورة الرئيسية ذات أبعاد ثابتة ونسخ WebP متجاوبة، مع التحميل المؤجل للصور خارج الشاشة.

## الاختبارات

بعد تشغيل الموقع في بيئة محلية مخصصة للاختبار، استخدم:

```bash
APP_ENV=local php tests/smoke.php http://127.0.0.1:8080 admin@example.com 'your-test-password'
```

الاختبار محمي من التشغيل عندما لا تكون `APP_ENV=local`. يغطي الصفحات الأربع واللغات الثلاث، الاتجاهات، 404، sitemap، بيانات SEO، ترويسات الأمان، نجاح وفشل نموذج التواصل، تسجيل الدخول، المسودة والمعاينة والنشر، تحرير الخدمات، الإعدادات، تغيير حالة الطلب، ورفع ملف صالح ورفض ملف غير صالح ومنع تنفيذ الرفع. ينظف تغييرات المحتوى والرفع التي ينشئها أثناء التنفيذ.

راجع [docs/qa-report.md](docs/qa-report.md) لنتيجة الاختبار المنفّذ فعلياً، و[docs/content-gaps.md](docs/content-gaps.md) للمعلومات غير المتوفرة.

### معاينات واختبار التصميم

صور حقيقية للصفحات الأربع على الهاتف والتابلت والحاسوب متاحة في [previews/README.md](previews/README.md). تحديث الهوية موجود في `public/assets/css/identity.css`، ويستخدم خط Noto Sans Arabic محلياً؛ لا يتطلب الموقع خدمة خطوط خارجية أو أدوات بناء JavaScript.

ملف `tests/visual.mjs` يفحص الواجهات باللغات الثلاث وأربعة مقاسات، دون إرسال طلبات أو تعديل المحتوى الإداري. يحتاج Node.js وحزمة `playwright-core` ومتصفح Chromium للاختبار فقط، وليس لتشغيل الموقع. يمكن تحديد مسار الحزمة عبر `PLAYWRIGHT_MODULE` ومسار المتصفح عبر `PLAYWRIGHT_EXECUTABLE`، ثم تشغيل `node tests/visual.mjs`. يكتب الصور والنتائج إلى `previews/`؛ ويمكن تغيير رابط الاختبار عبر `BASE_URL`.

### فيديو الافتتاحية والسلايدر

تستخدم الشريحة الأولى نسخة محسنة من الملف المرفق `bg.mp4` كخلفية، والثانية نسخة من `bg2.mp4`. الملفان الأصليان باقِيان دون تعديل؛ النسخ المستخدمة والصور البديلة داخل `public/assets/video/`، والمصادر موثقة في [docs/media-sources.md](docs/media-sources.md).

- تشغيل صامت داخل الصفحة، بدقة 720p للشاشات حتى 860px، و1080p للشاشات الأكبر.
- يُحمَّل الفيديو عند ظهور شريحته فقط، ويُوقف عند الانتقال منها أو خروج السلايدر من الشاشة أو إخفاء تبويب المتصفح.
- زر الإيقاف يتحكم بالفيديو وبالتنقل التلقائي معاً. ينتقل السلايدر فور انتهاء الفيديو فعلياً، دون مؤقت يقطع المقطع أو تكرار للفيديو نفسه. شريط التقدم يتبع موضع تشغيله، ويبدأ المقطع من أوله عند العودة إليه. الشريحة الثابتة والصور البديلة تنتقل بعد 6.5 ثوانٍ.
- وجود مؤشر الماوس فوق السلايدر لا يعطل الانتقال. التركيز بلوحة المفاتيح على رابط داخل محتوى الشريحة يوقفها مؤقتاً للحفاظ على العنصر المركّز؛ أزرار التنقل الثابتة لا تمنع الانتقال التلقائي.
- عند تقليل الحركة أو تفعيل توفير البيانات لا يُحمَّل الفيديو. وعند منع التشغيل التلقائي أو فشل التحميل تظهر لقطة ثابتة بديلة؛ تبقى الصفحة قابلة للقراءة دون JavaScript.
- يدعم خادم PHP المحلي طلبات MP4 الجزئية عبر `app/serve_video.php` و`router.php`. عند الرفع، تُقدَّم هذه الملفات الثابتة عبر Apache/Nginx مع MIME `video/mp4` ودعم HTTP Range.

اختبار الفيديو المستقل: `node tests/video.mjs` مع إعداد متغيرات Playwright المذكورة أعلاه. يتحقق من التشغيل والإيقاف والتحميل المؤجل والصور البديلة وطلبات Range دون تعديل قاعدة البيانات. النتائج والصور الفعلية داخل `previews/video-*`.

اختبار الانتقال عند نهاية المقطع: `node tests/video-ended.mjs` بالإعدادات نفسها؛ يشمل دورة كاملة ونهاية الفيديو الحقيقية والتوقف قرب النهاية والرجوع للبداية وعدم استخدام مؤقت الصورة لقطع الفيديو.

### قائمة الخدمات في الترويسة

تضم «خدماتنا» رابط صفحة الخدمات كاملة، ثم روابط مباشرة لتفاصيل الخدمات داخل الصفحة نفسها. تُقرأ الأسماء والترتيب والظهور من الخدمات المنشورة في قاعدة البيانات لكل لغة؛ يكفي تعديلها من لوحة الإدارة لتحديث القائمة.

تفتح القائمة بالنقر أو اللمس أو Enter، وتدعم الأسهم وHome وEnd، وتغلق بـ Escape أو النقر خارجها. يحتفظ تبديل اللغة بالخدمة المختارة. تعمل الروابط والقائمة الأساسية أيضاً دون JavaScript.

اختبار التنقل العام، دون تعديل قاعدة البيانات: `node tests/navigation.mjs` مع متغيرات Playwright المذكورة أعلاه. النتائج في `previews/navigation-checks.json`، والمعاينات في `previews/services-menu-*`.

اختبار تفعيل روابط القائمة عبر محركين: `MENU_ENGINE=webkit node tests/menu-links.mjs` ثم `MENU_ENGINE=chromium node tests/menu-links.mjs`، مع `PLAYWRIGHT_MODULE` عند الحاجة. يتطلب تثبيت محرك WebKit الخاص بـ Playwright؛ حدّد `PLAYWRIGHT_EXECUTABLE` فقط عند استخدام متصفح مناسب للمحرك المختار. يفحص النقر واللمس ولوحة المفاتيح، بما في ذلك اختلاف تركيز WebKit الذي كان يغلق القائمة قبل اكتمال النقر. النتائج في `previews/menu-links-webkit.json` و`previews/menu-links-chromium.json`.
